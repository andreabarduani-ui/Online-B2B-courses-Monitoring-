# Data and Analytics for Online Courses Monitoring

End-to-end Python pipeline that turns raw e-learning platform access logs into a
compliance-ready **monthly monitoring report** for subsidized vocational training
programmes.

Built for the Italian *formazione finanziata* (funded training) context, where
trainee hours must be tracked **while a course is running** to prove that the
hours claimed to the funding body comply with recognition rules: max 8
recognizable hours per day, no evening/night study beyond tolerance, no
early-morning cramming, and a cap of 150 funded hours per learner.

## ✨ What it does

- Auto-detects the input files in the working folder (LMS access export +
  employer attendance register)
- Produces **one Excel workbook** with one sheet per month plus a **General
  Summary** sheet with per-learner totals across months
- Classifies every hour of platform usage into *effective* vs *excess*:
  evening (after 18:00), weekend, early-morning window (06:00–07:40), and
  over-cap hours
- **Mode B**: cross-checks the LMS log against the employer attendance register
  (LUL) so that hours are only recognized on days the employee actually worked,
  capped to the worked hours of that day
- Fuzzy name matching between LMS export and attendance register (handles
  truncated and swapped first/last names)
- Cell-level notes with totals/excess breakdown, color coding, and live SUM
  formulas in Excel

## 🚀 Quickstart

```bash
git clone https://github.com/<your-username>/online-courses-monitoring.git
cd online-courses-monitoring
pip install -r requirements.txt

# 1. generate the synthetic demo dataset (LMS export + attendance register)
python generate_sample_data.py

# 2. run the monitoring pipeline
python training_hours_monitor.py
```

Output: `Monitoring_Report_<dd-mm-yyyy>.xlsx` — open it and check the monthly
sheets and the *General Summary*.

> The demo dataset is **fully synthetic** (random names, tax IDs and emails,
> fixed seed): every profile of usage the engine can classify is deliberately
> included (evening learners, weekend learners, early-morning learners,
> multi-session heavy users, employees vs external learners).

## 📏 Recognition rules

| Rule | Value |
|---|---|
| Daily recognition cap | 8 h / learner / day |
| Evening excess | platform hours after 18:00 |
| Early-morning excess | 06:00 – 07:40 window |
| Weekend excess | Saturday & Sunday |
| Funded-hour cap per learner | 150 h |
| Tolerance | 20 min |

All thresholds are configurable constants at the top of
`training_hours_monitor.py`.

## 📥 Input formats

### 1. LMS access export (`Report_Accessi.csv`, semicolon-separated, UTF-8 BOM)

| Column | Meaning |
|---|---|
| `Azienda` | Company |
| `Email` | Learner email |
| `Nome Cognome` | Full name |
| `Codice Fiscale` | Italian tax ID — **unique learner key** |
| `Percorso` | Training programme |
| `Giorno` | Date (`dd/mm/yyyy`) |
| `Primo Accesso` | First login time (`HH:MM:SS`) |
| `Ultimo Accesso` | Last logout time (`HH:MM:SS`) |
| `Totale Ore` | Session duration (`Xh Ymin Zs`) |
| `Corso` | Course title |

Column names are kept in Italian because they mirror the real LMS export the
tool was built to parse.

### 2. Attendance register — LUL (`Presenze.xlsx` or `Presenze.pdf`, optional)

One block per employee: a `Dipendente:` header row, a `LAV` row with worked
hours aligned to the day columns (`1 L`, `2 M`, …), and an optional
`A S S E N Z E` (absences) section with Italian absence codes (F, M, ROL, …).
When the register is present, the pipeline runs in **Mode B** for that month;
otherwise it falls back to **Mode A** (LMS log only, internal 8 h/day cap).

## 📤 Output

One sheet per month — one row per learner, one column per day (daily cells show
*effective* hours; cell notes show totals and excess breakdown) — plus summary
columns: `Total Effective Hours`, `Total Hours`, `Total Excess`, `Weekend
Excess`, `Evening Excess`, `Early-Morning Excess` (and `Worked-Hours Excess` in
Mode B).

The **General Summary** sheet shows one row per learner × one column per month,
with totals, progress towards the 150 h funded cap and hours exceeding it.

## 🔒 Privacy

This repository contains **no real personal data**: everything under
`sample_data/` is generated by `generate_sample_data.py` with random identities.
In production this tool processes personal data (names, tax IDs, attendance):
deploy it in compliance with GDPR and your local funding-body regulations.
